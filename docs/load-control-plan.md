# Этап 2: управление реальной LED-нагрузкой

Статус: **hardware bring-up / plan**. На этом этапе firmware не меняем.

Ветка этапа: `feature/load-control-stage`  
Базовое состояние `main` на старте этапа: `70b261854a51807a597a1aebdb468de0c86ad95b`.

Цель — перейти от проверенного стенда `ESP32-C3 -> тестовые LED` к управлению реальной нагрузкой:

```text
230 VAC
  ↓
Mean Well LPV-35-12
  ↓ 12 V
Mean Well LDH-25-350W
  ↓ 350 mA CC
LED-сборка (~36 V)

ESP32-C3 PWM
  ↓
PC817
  ↓
BC548
  ↓
DIM+ / DIM- LDH-25-350W
```

Сначала подтверждаем **один эталонный канал**, затем размножаем его на четыре.

## 1. Состояние проекта перед этапом

### Контроллер

Primary platform: **ESP32-C3 SuperMini**, распиновка проверена на железе.

```text
PWM CH1    GPIO0
PWM CH2    GPIO1
PWM CH3    GPIO3
PWM CH4    GPIO4

BTN1       GPIO5  -> GND
BTN2       GPIO6  -> GND
BTN3       GPIO7  -> GND
BTN4       GPIO10 -> GND
MASTER     GPIO20 -> GND
```

Текущая логика firmware:

- 4 независимых канала + master;
- PWM 1 kHz;
- рабочая яркость 10–100%;
- GPIO/PWM active HIGH: `0% = OFF`, `100% = full ON`;
- short press — toggle ON/OFF;
- hold — fade;
- master: any ON -> ALL OFF, all OFF -> ALL ON;
- после reboot логическое состояние каналов OFF;
- ESP8266 остается legacy compatibility target.

- `main` собирался успешно для `esp32c3` и `nodemcuv2`;

## 2. Реальная нагрузка одного тестового канала

Имеющаяся рабочая связка:

```text
LPV-35-12 -> LDH-25-350W -> LED-сборка
```

Подтверждено:

- питание LDH: **12 V**;
- драйвер: **Mean Well LDH-25-350W**;
- ток LED: **350 mA constant current**;
- рабочее напряжение LED-сборки: около **36 V**;
- между `DIM+` и `DIM-` при открытом DIM измерено около **10 V**;
- LPV-35-12: **12 V / 3 A**, подходит для теста одного канала.

По официальному datasheet LDH-25-350W:

- input: 9.5–32 VDC;
- output: 12.5–72 VDC / 350 mA;
- dimming: 0–10 V DC или 10 V PWM;
- PWM frequency: **1–3 kHz** — текущие 1 kHz подходят;
- минимальный определенный уровень диммирования около 8%;
- при DIM OFF выходное напряжение LDH падает примерно до входного;
- `DIM-` **нельзя соединять с `Vout-`**.

При 12 V на входе и LED-сборке около 36 V ожидаем полный dark при DIM OFF, потому что выход LDH в этом состоянии около входных 12 V и этого недостаточно для свечения данной LED-цепочки.

## 4. Целевая схема одного канала

### 4.1 Сторона ESP32-C3

```text
PWM GPIO ─────── 500 Ω ───────►|──── GND
                              PC817

PWM GPIO ─────── 10 kΩ ─────── GND
                 pull-down
```

Ориентировочный ток LED PC817 при HIGH:

```text
(3.3 V - ~1.2 V) / 500 Ω ≈ 4.2 mA
```

Это близко к режиму 5 mA, для которого Sharp нормирует CTR PC817. Hardware pull-down сохраняет состояние OFF при boot/reset/Hi-Z.

### 4.2 Сторона LDH

BC548 используется как ключ, который в fail-safe состоянии замыкает `DIM+` на `DIM-`.

```text
                         LDH-25-350W

DIM+ (~10 V open) ───────┬──────────── C
                         │             │
                        10 kΩ        BC548
                         │             │
                         ├──── BASE    E
                         │             │
                   C  PC817           DIM-
                   E    │
                        └───────────── DIM-
```

PC817 output:

```text
collector -> BASE BC548
emitter   -> DIM-
```

BC548:

```text
collector -> DIM+
emitter   -> DIM-
base      -> 10 kΩ к DIM+ + collector PC817
```

Резистор 50 kΩ `BASE -> DIM-` считаем **опциональным**. Первый тест выполняем без него, если базовый узел стабилен; добавляем только если появится конкретная причина.

**Важно:** физический pinout конкретного BC548 нужно проверить перед подключением. В плане используются только обозначения `C/B/E`; расположение ножек не угадываем по внешнему виду.

### 4.3 Логика

```text
GPIO LOW
 -> PC817 OFF
 -> 10 kΩ поднимает BASE BC548
 -> BC548 ON
 -> DIM+ ≈ DIM-
 -> LDH OFF

GPIO HIGH
 -> PC817 ON
 -> BASE BC548 стягивается к DIM-
 -> BC548 OFF
 -> DIM открыт / около 10 V
 -> LDH ON
```

Ожидаем сохранение текущей software-семантики без инверсии:

```text
0%   -> OFF
10%  -> ~10%
50%  -> ~50%
100% -> full ON
```

Если hardware test показывает обратную полярность или нелинейность, сначала фиксируем измерения и только потом решаем, менять ли схему или firmware.

## 5. Fail-safe цель

Для реальной нагрузки отсутствие управляющего сигнала должно приводить к **OFF**.

```text
ESP выключен / GPIO Hi-Z
 -> hardware pull-down
 -> PC817 OFF
 -> BC548 ON
 -> DIM short
 -> LDH OFF
```

То же ожидается при reset ESP.

PC817 изолирует **управляющий PWM-путь**, но это не означает автоматически полную гальваническую развязку всей системы: ESP питается через неизолированный DC/DC от той же 12 V системы. Поэтому намеренно не соединяем `ESP GND` с `DIM-` или `Vout-`; возможные внутренние/силовые связи проверяем отдельно на полностью обесточенной схеме.

## 6. Питание контроллера

```text
LPV-35-12 12 V
   ├──> LDH-25-350W Vin+ / Vin-
   │
   └──> DC/DC buck IN+ / IN-
             ↓
            5.00 V
             ↓
        ESP32-C3 5V / GND
```

Перед подключением ESP:

1. Подключить DC/DC только к 12 V.
2. Выставить мультиметром 5.00 V.
3. Проверить полярность OUT+/OUT-.
4. Убедиться, что current limit CC не выставлен слишком низко.
5. Перепроверить 5 V после нескольких включений.
6. Только затем подключать ESP.

Дополнительная фильтрация для финальной сборки:

- 150 nF рядом с питанием контроллера;
- 100 µF / 16 V на 5 V рядом с ESP;
- 1000 µF / 25 V на 12 V — после проверки необходимости и физического размещения.

Для первого функционального теста дополнительные электролиты не обязательны.

## 7. Безопасность при bring-up

Сетевую часть LPV считаем отдельным готовым узлом.

- не собирать 230 VAC на breadboard;
- не менять соединения первичной стороны под напряжением;
- все измерения/перекоммутации `PC817 / BC548 / DIM / ESP` выполнять на низковольтной стороне;
- перед прозвонкой или перестановкой проводов полностью обесточить LPV;
- помнить, что выход LDH — не «12 V линия»: драйвер может поднимать выход до десятков вольт, а по datasheet для этой модели рабочий диапазон достигает 72 V и OVP еще выше;
- `DIM-` не соединять с `Vout-`.

## 8. Bring-up одного канала

### A. Проверить исходную силовую связку

Без ESP/PC817:

- LPV -> LDH -> LED;
- DIM открыт;
- LED стабильно full ON;
- повторно измерить `DIM+ - DIM-` — ожидаем около 10 V.

### B. Проверить DIM вручную

Кратковременно замкнуть `DIM+` на `DIM-`:

- LED должен полностью погаснуть;
- после размыкания вернуться на full ON.

### C. Проверить только BC548

Без PC817 и ESP:

```text
C -> DIM+
E -> DIM-
10 kΩ: DIM+ -> B
```

Ожидание: BC548 открыт, свет OFF.

Временно стянуть BASE к DIM-:

- BC548 должен закрыться;
- свет должен включиться.

Дополнительно измерить `DIM+ - DIM-` в обоих состояниях. В OFF желательно увидеть близкое к нулю напряжение; фактическое значение зафиксировать.

### D. Добавить PC817

- PC817 input OFF -> свет OFF;
- PC817 input ON от 3.3 V через 500 Ω -> свет ON.

Зафиксировать напряжения `DIM+ - DIM-` для обоих состояний.

### E. Подключить ESP32-C3

Сначала проверить только:

```text
0%   -> OFF
100% -> full ON
```

Затем:

```text
10%
25%
50%
75%
100%
```

Проверяем отсутствие видимого мерцания и монотонное изменение яркости.

### F. Проверить пользовательскую логику

- short ON/OFF;
- hold из ON;
- hold из OFF;
- сохранение brightness в RAM;
- master OFF/ON;
- master во время hold.

### G. Boot / fail-safe tests

При уже запитанном LDH:

1. ESP выключен -> LED OFF.
2. Подать питание на ESP -> вспышки нет.
3. Reset ESP -> вспышки нет.
4. Отключить питание ESP при включенном канале -> LED уходит в OFF.
5. Несколько циклов общего power-on/power-off.

### H. Длительный тест

30–60 минут на:

- 100%;
- 50%;
- около 10%.

Контролируем:

- нагрев LDH;
- нагрев DC/DC;
- нагрев BC548;
- стабильность ESP;
- отсутствие вспышек, зависаний и рестартов.

## 9. Масштабирование на четыре канала

После успешного одного канала повторяем одинаковый узел `PC817 + BC548 + resistors` четыре раза.

```text
GPIO0 -> power interface #1
GPIO1 -> power interface #2
GPIO3 -> power interface #3
GPIO4 -> power interface #4
```

Каждый LDH получает собственную DIM-обвязку. `DIM-` разных LDH не объединяем без отдельного подтверждения силовой топологии.

### Мощность

Один LED-канал:

```text
36 V * 0.35 A ≈ 12.6 W
```

Четыре канала — около 50 W только на LED, плюс потери LDH и контроллер.

Один LPV-35-12 (12 V / 3 A) **не является общим финальным БП для четырех каналов**.

Варианты финального питания:

1. отдельный 12 V источник на канал;
2. один общий 12 V источник достаточной мощности.

Если используем общий БП, предварительный ориентир — **минимум 6 A**, разумный запас около **8 A**. Финальное значение выбираем после измерения фактического входного тока одного полностью собранного канала на 100%.

## 10. Известные firmware-вопросы перед финальной эксплуатацией

Код сейчас не меняем, но для реальной нагрузки сохраняем backlog.

### 10.1 Зажатая кнопка при boot

Текущая state-machine может воспринять физически зажатую кнопку после reboot как новое нажатие.

Предпочтительное правило для финального устройства:

```text
boot -> outputs OFF
если input уже pressed -> ignore until first physical release
после release -> input armed
```

Особенно проверить master.

### 10.2 Направление hold после master cancel

`cancelInteractionUntilRelease()` останавливает hold, но не обязательно продвигает `nextHoldDirection_` так же, как обычный `stopHoldFade()`.

Это UX-вопрос, не hardware blocker.

### 10.3 Debounce + ignoreUntilRelease

Есть редкий timing edge case при master cancel между raw/stable debounce состояниями. Перед production release его нужно отдельно воспроизвести и решить.

## 11. Acceptance criteria

### Один канал

- [ ] DC/DC стабильно дает 5.00 V.
- [ ] DIM open -> full ON.
- [ ] DIM short -> полный OFF.
- [ ] GPIO LOW -> load OFF.
- [ ] GPIO HIGH -> load full ON.
- [ ] PWM 1 kHz корректно управляет LDH.
- [ ] 10/25/50/75/100% дают монотонное изменение яркости.
- [ ] ESP power loss -> load OFF.
- [ ] ESP reset -> нет вспышки.
- [ ] short/hold/master работают на реальной нагрузке.
- [ ] 30–60 минут работы без перегрева/сбоев.

### Четыре канала

- [ ] Все четыре канала независимы.
- [ ] Master работает на всех нагрузках.
- [ ] Одновременный full ON не вызывает просадку питания/reset ESP.
- [ ] Нет взаимного влияния DIM-каналов.
- [ ] Общий источник питания имеет измеренный токовый запас.

## 12. Что сознательно не делаем до подтверждения одного канала

- не меняем firmware;
- не меняем PWM frequency;
- не вводим software inversion;
- не переносим схему сразу на 4 канала;
- не проектируем финальную PCB;
- не выпускаем production release.

Сначала подтверждаем эталонный канал измерениями, затем фиксируем финальную схему и только после этого переходим к code/PCB/release этапу.
